| id | verdict | what changed or why |
|---|---|---|
| B1-1 | fixed | The ledger's partial list is now a `BTreeSet` (insert/remove/lookup no longer scan the whole list under the mutex, so 50k queued rows are no longer n^2). `save_now` stats the files outside the LEDGER lock and re-checks each missing one under it. The reservation itself is kept (the claim file is what makes disk-folded names unique), so resume and leftovers behave as before. |
| B1-3 | fixed | `Limiter::pause_unless` and `Lane::throttle_unless` end the throttle wait when the transfer's cancel/pause flag is set; the S3 and generic download loops use them. |
| B1-4 | fixed | S3 resume stops retrying at once on a 4xx answer other than 408/429 (412 object replaced, 404 deleted, 403), via `will_not_change`; network errors and 5xx still retry. |
| B1-5 | fixed (mostly already covered) | Per-folder errors, no batch after a stop: already done in the earlier change. Added: after a listing fails, a 300 ms grace lets in-flight batches land and later ones are ignored, so downloads don't start after the failure was reported; the error says "N of M folders couldn't be listed" when several failed. |
| B1-6 | fixed | `shutdown` writes the "paused" record only while the transfer is still in `ACTIVE`, under that lock; a transfer that finished meanwhile no longer gets a resurrected record. |
| B2-2 | not real now | Same root cause as B2-1, already fixed: `walk_parallel` finishes each group of listings before yielding, so no listing sits suspended while the consumer works. |
| B2-4 | fixed (S3) / skipped (generic) | S3 `copy_many` refuses a folder onto its ancestor only when a copy would land on one of the folder's own keys (key-level check like the DAL). Generic stores keep the blanket refusal: a WebDAV MOVE with overwrite or a live-walking `copy_through` onto the parent is unsafe, and the DAL already checks keys for its stores. |
| B2-5 | fixed (S3) / skipped (FTP overlap) | `reconnect_connection` now also drops the cached S3 client. The short FTP double-pool overlap is left: transfers hold the old pool, and the cure (draining or sharing pools) is invasive for a low-impact case. |
| B2-6 | fixed | `name_refused` no longer accepts a PermissionDenied kind outright; it needs the path-stripped reply words to be about the name or permissions, with a test for a folder called "Permission Slips". |
