# Round 6 fixes, area security (S-1 to S-9, B3-6)

| id | verdict | what changed or why |
|---|---|---|
| S-1 | fixed | `check_template` (actions.rs) and `templateProblem` (templateCheck.ts) now refuse a template that has any placeholder and evaluates anything: `$((`, `((`, `$[`, `let`, `-eq/-ne/-lt/-le/-gt/-ge`, `integer`, `float`, `declare/typeset/local/export/readonly` with `-i`/`-F`/`-E`, an array index (`${a[…]}`, `$a[…]`, `a[…]=`), and `eval`, with plain-English messages. Inside `[[ … ]]`, `&`, `\|`, `(`, `)` no longer end the command (operand check sees the whole test). `exit/return/break/continue/shift/logout/repeat/vared/ulimit {x}` and `print -v` join the operand deny-list. Every S.md row is in template-vectors.json (shared by Rust and TS); `echo $((1 + 2)) {name}` moved from ok to bad as the new rule requires; two real-bash cases added to `round5_refusals_really_run_names`. |
| S-2 | fixed | `directory()` in zipCheck.ts now accepts only a plain layout and refuses anything else ("unusual zip layout"): bytes before the first part, a zip comment or trailing bytes, a directory that does not end exactly at the end record (or ZIP64 record), entries beyond the counted ones, a ZIP64 locator JSZip would ignore, and uses JSZip's own ZIP64 triggers (disk/count/size/offset at max). A prefixed zip is no longer reported as "not a zip". Tests for prefix, ZIP64 trigger, comment, understated count, gap. Not done: the low-confidence variants (missing `DecompressionStream` falls back to headers; local-header ZIP64 extra). Refusing every Office file with a deflated photo on a web view without raw-deflate would break previews for a case I could not show is real. |
| S-3 | fixed | `password_target` now covers Azure and GCS: target = endpoint origin (scheme, host, port; the service's own address when empty) plus, for Azure, the account. `save_profile` and `test_connection` already call `password_moved`, so both demand the key again on a change. BlobForm uses new `blobTarget` (kinds.ts) instead of the account-only compare, with matching messages. Applies to account keys too (same rule the form already had for a new account), not only SAS, so form and backend agree without the form knowing the secret's type. Tests in Rust and TS. |
| S-4 | fixed | Target is built from the functions the connection uses: FTP/SFTP use `socket_addr` (port typed in the host field counts), WebDAV uses the first `candidate_urls` URL (scheme, host, port; `dav://` is plain http, `davs://` https, odd schemes http). TS mirror updated (`portInHost`, `davOrigin`, `originOf`). |
| B3-6 | fixed | Transport is in the target: FTP `tls` (Explicit/Implicit) vs `plain` (None/Auto, since Auto falls back to plain), WebDAV scheme. Going from TLS to plain, or https to http, asks for the password again. Switching plain to TLS asks too (accepted cost of one rule). |
| S-5 | fixed | logText.ts redacts `tempauth`, `upload_id`, `x-goog-*`, `SharedAccessSignature`, `access_key`, `auth` params, any `Signature=`, `Cookie`/`Set-Cookie`/`X-Auth-Token` lines, JSON `token`/`id_token`/`SessionToken`, `*SECRET*=` env names, and strips the `kybl:<32 hex>` trust tag. Rust `net_error` (oauth/http.rs) drops the URL from the reqwest text before it becomes a detail (`without_url`). Not done: multi-word `password: a b` and `/` or extra `@` in URL passwords (heuristics that would redact normal sentences). |
| S-6 | fixed | Scheme part of the URL regex capped at 32 characters, so the scan is linear (test with 120 000 characters). |
| S-7 | skipped | The dialog already says that text is hidden and how much; only pastes over 64 KB are affected and a virtual list for the middle is a feature, not a fix. Refusing big multi-line pastes would break legitimate ones. |
| S-8 | fixed | `ln -- "$T" {f}` and `mv -- "$T" {f}` in `compress_script`, so a folder named `-sf` zips on a GNU server. |
| S-9 | fixed | Shortened partial name uses 64 bits of the MD5 instead of 32. Old partials of 249-255 byte names are simply not resumed (restart). Not done: recording the etag in a sidecar (final hash check remains the backstop). |
